Calm dashboard: one next step, a dark black-and-white look, and a folder picker

After the first pod-trial run, the human found screen 1 too busy: every panel and control showed at once, with big gaps on a phone. This plan made it calm. You open the board and see in a couple of seconds what pod needs from you, if anything, and the one button to do it. Everything else is one click away.

1. At a glance

Goal (from the plan): make screen 1 calm, move the whole board to a dark-first, black-and-white look in the style of Vercel, and let + Repo pick a folder from a folder browser instead of a typed path.

What shipped:

  • A Next step card for the selected run: the most urgent item and its one button, or a quiet "Nothing to do".
  • Waiting, Plan and Log tabs under the card, all closed at start, the open one remembered per browser.
  • A bar with + Repo and a ⋯ menu (auto-continue, theme, ports), and a run header with a progress strip.
  • A folder picker backed by a new token-guarded GET /api/fs/folders.
  • The new look on every screen: Geist fonts, self-hosted; Dark by default; every state shown as a dot plus a word.

Differences from the approved overview, and why:

  • A new readGuard on /api/fs/*. The overview showed a route and a listing module. The sprint contract added a GET guard: browsers leave Origin off same-origin GETs, so actionGuard, which needs one, couldn't guard a read.
  • One "Next step" module became six pure modules. Each slice kept its logic in a tested .ts file, the project rule that components are glue.
  • manifest.webmanifest and pwa.test.ts changed. No slice owned them. L1 couldn't pass pnpm verify with the old light manifest color, and the human chose dark at gate 1.
  • AnswerForm split out, ReplyPanel gained framed. This let the card show the Answer form and a reply's rows itself.

4. Key decisions

The plan's own decisions were made with the human in the plan interview, and most have no decisions.md entry. The links point to the plan instead.

A Vercel-style, dark-first, black-and-white look

Why
The human picked direction C, simplified, then redrawn "like Vercel".
Instead of
Drafts A and B; keeping the board-read look (slate and cobalt, chips, colored card edges).
So
Every state is a dot plus a word; the 2026-10-19 ink-token decision is obsolete.
Who
human in planning; L1 recorded the rule
Link
plan Look · decisions.md

Dark by default; manifest colors follow

Why
Nothing stored now reads as Dark. At gate 1, so no white splash shows before a dark page.
Instead of
System as the default; a #ffffff manifest (reply light).
So
Manifest #000000; pwa.test.ts reads the dark tokens.
Who
human in planning and at gate 1 (answer: dark)
Link
decisions.md

One Next step card, for the selected run only

Why
The old screen showed every control at once. Order: BLOCKED, a PR to merge, a reply, other PENDING.
Instead of
A card across all runs (parked as an idea).
So
Built only from the model's rules, so it can't disagree with old panels.
Who
human in planning
Link
plan (no decisions.md entry)

A BLOCKED halt beats a PR; a PENDING gate stop doesn't

Why
The contract said a halt is always the card, but its tier order put a PR first.
Instead of
Any autopilot halt takes the card.
So
At gate 6 the held-back PR takes the card; the halt sits in Waiting.
Who
agent N1; default recorded at plan end
Link
decisions.md

Tabs start closed; the open tab is per browser

Why
So the page ends under the card. The Pipeline / Wave board tabs at the top go.
Instead of
Sections open at start; a tab per run.
So
pod-board-tab in localStorage; the wave board opens from the Plan tab.
Who
human in planning
Link
plan (no decisions.md entry)

A folder browser in the page, not the OS dialog

Why
No browser picker returns a full path. Syncthing, Jellyfin, Emby and Radarr list folders from the server, behind a key.
Instead of
A native dialog, which can open behind the browser (parked as an idea).
So
Every drive, folders only, pod-docs marks, behind the token and Host check.
Who
human in planning, from research
Link
plan (no decisions.md entry)

Add needs a whole folder name

Why
Posting the open folder would silently add the parent of what you typed.
Instead of
Add posts the listed folder whatever you typed.
So
Add is off for a partial name; the footer shows the exact path it posts.
Who
agent P1; default recorded
Link
decisions.md

Card wording and the "Run it yourself" note

Why
The plan named no wording. T1 also moved the no-session note behind Run it yourself to keep the card short.
Instead of
The note on the card itself.
So
E.g. Merge PR #N · "Wave W of <sprint> is handed back to you."

7. What's left

Fix next: none. Before hosting: none.

Someday (all open entries this plan left in the queue):

  • Listing: a link in the middle of a typed path that points to \\host\share is followed; only the last part is checked (folder-list.ts). No repro.
