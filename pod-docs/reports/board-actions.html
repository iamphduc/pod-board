Pod Board, phase 2: approve from the board

This plan lets the human do pod's hand-offs from the board instead of the chat: merge a PR that waits on them, answer a queue entry, and send continue or go to the run.

1. At a glance

Goal: let the human approve from the board. Every action must do exactly what the human would do by hand, so pod picks it up the same way and the board never breaks a run.

What shipped:

  • A Merge button on any PR that waits on you (wave, fix, or final plan PR), with a confirm step and GitHub's real result.
  • A Waiting on you list with an answer form that appends **Answer (human):** <text> to the queue entry's line.
  • A Reply panel naming the reply pod waits for and the session to paste it in, with Copy.
  • Continue and Go buttons, and an opt-in auto-continue switch per run that sends only continue.
  • An action log, and a per-launch token with Host and Origin checks on every action.

API

All routes are POST under /api/actions/, behind the action guard: Host, Origin, POST only, application/json, X-Pod-Board-Token, and a JSON object body, checked in that order.
